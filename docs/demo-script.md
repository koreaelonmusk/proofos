# ProofOS — 4분 데모 대본

**핵심 한 문장:** AI가 완료를 선언했고, 시스템이 독립적 증거가 나올 때까지 거부했다.

심사위원이 30초 안에 이해해야 하는 것은 그 한 장면입니다. 나머지 시간은 "그게 왜 속일 수 없는가"를 보여주는 데 씁니다.

---

## 사전 준비 (발표 전에 완료)

```powershell
cd C:\Users\User\Downloads\proofos-p0\proofos-1
docker compose -f docker-compose.yml -f docker-compose.live.yml up -d --build
curl -s http://127.0.0.1:8080/config
```

`agent_runtime: gemini`, `live_model_enabled: true`, `attested_evidence: true`가 나와야 시작할 수 있습니다.

**주의 — Gemini 무료 등급은 하루 20요청입니다.** 전체 실행 1회가 약 10요청을 씁니다. 리허설은 `PROOFOS_AGENT_RUNTIME=deterministic`으로 하고, 실제 발표에서만 라이브를 쓰세요. 유료 키가 있으면 이 제약은 사라집니다.

**백업:** 라이브 실행이 실패할 경우를 대비해 `artifacts/live-gemini-proof.json`을 열어둘 것. 실제 실행 기록이므로 그대로 보여주면 됩니다.

## 1:00 – 2:30 · 라이브 실행

```powershell
python -m proofos_agent.run_demo
```

출력이 나오면 **세 지점만** 짚으세요.

### ① 거부 (가장 중요한 순간)

```
attempt 1: ABSTAIN   EVIDENCE_UNTRUSTED   missing=['runtime']
```

> "실행자가 '서비스 정상입니다'라고 했습니다. 시스템이 거부했습니다.
>
> 이유는 `EVIDENCE_UNTRUSTED` — **자기 자신에 대한 보고이기 때문**입니다. 실행자의 말은 증거가 아닙니다."

### ② 독립적 수집

```
COLLECTION_REQUESTED        collector-http-v1
ATTESTATION_ACCEPTED        collector-http-v1  HEALTHY
```

> "런타임이 **별도 프로세스**에 실제 관측을 요청합니다. 그 프로세스가 진짜 HTTP 요청을 보내고, 결과에 Ed25519로 서명합니다.
>
> 서명 키는 그 프로세스에만 있습니다. API는 서명을 **검증**할 수는 있어도 **만들 수는 없습니다**."

### ③ 승인

```
attempt 2: VERIFIED

evidence:  runtime  EXECUTOR  by executor-v1        ← 거부됨
           runtime  OBSERVED  by collector-http-v1  ← 인정됨
```

> "같은 종류의 증거가 둘 있습니다. 하나는 실행자의 말, 하나는 서명된 관측.
>
> 시스템은 두 번째만 인정합니다."

## 2:30 – 3:30 · 왜 속일 수 없는가

세 가지만 말하세요. 각각 실제로 테스트돼 있습니다.

**1. 모델은 증거를 만들 수 없습니다**

> "Verifier가 쓰는 도구는 파라미터가 두 개뿐입니다 — `task_id`와 `claim`. 증거가 있다고 주장할 필드 자체가 없습니다.
>
> 초기 버전에는 `has_runtime_evidence`라는 불리언이 있었습니다. 모델이 그걸 `true`로 넘기면 통과였습니다. **검증기가 장식품이었습니다.** 그 구멍을 막은 게 이 프로젝트의 출발점입니다."

**2. 모델의 말은 판단이 아닙니다**

> "Verifier 모델이 'VERIFIED'라고 써도, 도구 결과가 `ABSTAIN`이면 시스템은 `ABSTAIN`입니다.
>
> 모델 출력은 설명이고, 판단은 결정론적 코드가 합니다."

**3. 증거는 위조도 재사용도 안 됩니다**

> "서명은 실행 ID·작업 ID·시각·nonce를 전부 포함합니다. 다른 실행에서 재생하면 거부되고, 한 글자만 바꿔도 서명이 깨집니다.
>
> 전부 테스트로 증명돼 있습니다 — 429개."

여유가 있으면 감사 추적을 보여주세요:

```powershell
curl -s "http://127.0.0.1:8080/executions/<execution_id>" | python -m json.tool
```

> "모든 단계가 해시 체인으로 기록됩니다. 중간을 지우거나 순서를 바꾸면 체인이 깨집니다. **'왜 승인됐는가'를 에이전트의 요약이 아니라 기록으로 재구성할 수 있습니다.**"

## 예상 질문

**"모델을 그냥 더 좋은 걸 쓰면 되지 않나요?"**
> 아닙니다. 문제는 모델의 능력이 아니라 권한 구조입니다. 아무리 좋은 모델이라도 자기 작업을 자기가 검증하면 그건 증거가 아닙니다. GPT-5든 Gemini든 동일합니다.

**"수집기가 거짓말하면요?"**
> 수집기는 실제 관측만 서명할 수 있습니다. 응답이 오지 않으면 아무것도 기록하지 않습니다. 그리고 수집기는 판정을 내릴 수 없습니다 — 관측과 판단이 분리돼 있습니다.

**"프롬프트로 시키면 되지 않나요?"**
> 프롬프트는 신뢰 경계가 아닙니다. 경계는 코드·권한·객체 참조입니다. Executor는 "증거를 쓰지 마세요"라는 지시를 받는 게 아니라, **쓸 수단 자체가 없습니다.**

**"실제 클라우드에서 도나요?"**
> 아직입니다. 컨테이너 두 개로 로컬에서 증명했고, Cloud Run 배포는 결제 계정 문제로 미완입니다. **증명되지 않은 건 증명되지 않았다고 말합니다** — 그게 이 프로젝트의 태도이기도 합니다.
